# Is CHKPII relevant with GP?

CHKPII is still useful/relevant if you are working with “Legacy” file formats that are not natively supported by GP (e.g. XPG4 message files, MQSeries message files, CDE Help Files, CICS host message files, etc.). If your file format is not natively supported by GP and you have to use a “GP Filter” to import/export your file, then you may still want to use CHKPII to ensure that the source English file passes CHKPII so that it can be properly parsed by the GP filter on import.  Likewise, you may want to run CHKPII on the translated files after exporting them through the filter as the translator may have added newlines, or made other changes in the translated string that introduced errors into the expected formatting for the translated file generated by the GP filter on export that would cause build breaks or runtime issues.  Additionally, you may need to use CHKPII to determine the file format of the source English file to know which GP Filter to use when importing/exporting the file from GP as there are some file types that are quite similar but require a different GP Filter on import/export to properly handle certain peculiarities of the formatting.

Another use for CHKPII when working with “Legacy” files is that the encoding of the file may not be UTF-8 and CHKPII can report which encoding the translated file is in. Under this situation, we could leverage webFM.
